# AI Docent

## 1. Git 주소

https://github.com/HappyBird6/AI-Docent

## 2. 프로젝트 개요 및 실행 방법

### 개요

시카고 미술관 유럽 회화 100점을 한 점씩 감상하는 온라인 전시관입니다.
작품 이미지·작품명·작가·제작 시기를 보여주고, 작품별 도슨트 대화를 제공합니다.
RAG로 작품·작가·시대 배경 문서를 검색해 답변과 감상 가이드를 만들고 사용한 출처를 표시합니다.
HTML/CSS/JavaScript 프론트엔드, FastAPI 서버, Chroma Vector DB와 LangGraph를 사용합니다.

### 실행

Python 3.12와 SSAFY GMS 키가 필요합니다. 프로젝트 루트에서 Windows PowerShell로 실행합니다.
프론트엔드는 FastAPI가 함께 제공하므로 별도 빌드나 Streamlit 실행이 필요하지 않습니다.

```powershell
# 가상환경 생성 및 패키지 설치
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 환경변수 파일 준비: 기존 파일은 유지
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
```

`.env`에 `GMS_KEY`와 `WIKI_CONTACT`를 입력한 뒤 아래 명령을 실행합니다.
`WIKI_CONTACT`는 Wikipedia 요청 식별용 본인 이메일·HTTPS 연락 URL·`User:위키계정` 중 하나입니다.
키와 연락처는 저장소에 올리지 않습니다.

```powershell
# 작품 메타데이터 / 외부 문서 색인
.\.venv\Scripts\python.exe -m scripts.index_artworks
.\.venv\Scripts\python.exe -m scripts.index_documents

# 서버 실행
.\.venv\Scripts\python.exe -m backend.main
```

[전시관](http://127.0.0.1:7777)에 접속합니다. 기본 데이터는 메타데이터 100건·외부 문서 221개이며,
기본 청킹 설정으로 689개 문서 청크가 생성됩니다. 배포 데이터가 있으므로 최초 실행 시 원문 재수집은 필요하지 않습니다.
색인·AI 질문에는 네트워크와 GMS 사용량이 필요합니다. 키·색인 없이도 전시관 조회는 가능합니다.

환경변수를 바꿨다면 서버를 재시작합니다. 원문·청킹 설정을 바꿨다면 문서를 다시 색인합니다.
준비 상태와 누락 안내는 [도슨트 상태](http://127.0.0.1:7777/api/docent/status),
컬렉션 건수·청킹 설정은 [RAG 상태](http://127.0.0.1:7777/api/rag/status)에서 확인합니다.

## 3. 요구사항 정의서

- **도메인:** 미술작품 큐레이션·도슨트.
- **선택 근거:** 공개 회화 100점과 미술관·Wikipedia·OpenLearn 원문 221개를 확보했습니다.
  작품 정보와 외부 해설을 연결할 수 있고, 작가·시대 배경·작품 해석에는 출처 근거가 필요해 선택했습니다.
- **면책 안내:** 건강·금융 등 위험 판단 도메인에 대한 전문 조언 면책은 해당 없음입니다.
  AI 해설은 원문과 대조할 수 있으며 이미지 자체를 분석한 결과는 아닙니다.

근거가 필요한 질문 예시:

1. 이 작품의 색과 구도를 미술관 해설에서는 어떻게 설명하고 있어?
2. 이 작가의 생애와 활동 배경 중 문서로 확인되는 내용을 알려줘.
3. 이 작품 제작 당시의 사회·종교적 배경은 어떠했어?

`O`: 구현, `△`: 일부 대응·추가 확인 필요, `X`: 미구현·미작성입니다.

## 4. RAG 파이프라인 설계

### 처리 흐름

1. **수집:** 기본 미술관·Wikipedia·OpenLearn 문서를 준비합니다. 일반 질문에서는 검색어를 추출하고
   Wikipedia 후보를 수집한 뒤 LLM으로 선별합니다. 현재 작품의 미술관 원문은 필수로 포함합니다.
2. **청킹:** 외부 원문을 문단별로 분할합니다. OpenLearn은 선별된 문단 내부에서만 분할해 제외 자료를 다시 연결하지 않습니다.
3. **색인:** 작품 메타데이터와 외부 청크를 각각 임베딩해 별도 Chroma 컬렉션에 저장합니다.
   고정 ID·내용 해시로 변경분만 갱신하며, 질문별 추가 원문도 문서 컬렉션에 반영합니다.
4. **검색:** 현재 작품 메타데이터는 ID로 조회하고, 연결된 작품·작가·사조·시대 문서는 코사인 의미 검색합니다.
   시대 배경은 제작 시기·지역으로 후보를 제한하며 다른 작품의 대화는 섞지 않습니다.
5. **병합:** 작품 메타데이터와 외부 근거를 합치고 동일 청크·내용 중복을 제거합니다.
   작품 해설을 우선 포함하고 문서당 청크 수·전체 출처 수를 제한합니다.
6. **생성:** 검색 근거로 한국어 답변과 인용을 생성합니다. 인용 번호를 검증하고 실제 사용한 출처만 반환합니다.

실제 LangGraph는 두 노드이며, 검색어 추출·수집·선별·색인·검색·병합은 `retrieve` 안에서 수행합니다.

```mermaid
flowchart LR
    START --> retrieve
    retrieve --> generate
    generate --> END
```

### 컬렉션과 캐시

| 저장소 | 내용 | 기본 건수 |
| --- | --- | ---: |
| Chroma `artwork_metadata` | 작품별 검색 텍스트·미술관 대체 설명·원문 정보 | 100레코드 |
| Chroma `artwork_documents` | 작품·작가·사조·시대 배경 원문의 청크·출처 정보 | 689청크 |
| SQLite `.cache/collection/journal.sqlite3` | 검색 계획·검색어·후보·선별 이력·추가 원문·작품 연결 | 실행 중 생성 |

벡터 DB는 `.cache/chroma`에 저장합니다. 검색어 정규화와 영구 캐시로 완료한 검색·선별을 재사용하며,
임베딩 실패 시 선별 결과를 보존해 다음 요청에서 색인을 재개합니다. 추가 수집분은 기본 데이터 파일을 덮어쓰지 않습니다.
`.cache`는 Git에서 제외하므로 새 환경의 추가 문서·청크 수는 질문에 따라 달라집니다.

### 프롬프트 1/2/3

| 단계 | 입력·역할 | 출력 |
| --- | --- | --- |
| 1. 검색어 추출 | 미술사 전문가 역할, 현재 작품·질문·최근 사용자 질문 | `keywords`, `focus`, `external_queries` JSON |
| 2. 후보 선별 | 미술관 연구 사서 역할, 작품·질문·후보 제목/URL/요약 | `selected: [{id, kind, reason}]` JSON, 서버가 후보 ID·개수 검증 |
| 3. 답변 생성 | 한국어 도슨트 역할, 현재 작품·검색 근거·대화 문맥 | `[근거 N]`을 붙인 평문, 서버가 실제 사용 출처만 반환 |

채팅 모델은 SSAFY GMS의 `gpt-5.4-nano`, 임베딩 모델은 `text-embedding-3-small`입니다.
이전 대화는 질문의 지시 대상을 이해할 때만 사용하며 사실의 근거로 쓰지 않습니다.

### 설정값과 선택 이유

설정 파일: [`config/search.json`](config/search.json).

| 설정 | 값 | 이유 |
| --- | ---: | --- |
| 청크 크기 | 1000자 | 문맥을 유지하면서 모델 입력·발췌 길이 제한 |
| 청크 중복 | 200자 | 같은 문단의 연속 청크 사이 문맥 보존 |
| Top-k | 6 | 기본 정보 외 작품·작가·배경 청크를 함께 검색 |
| 최대 출처 수 | 5 | 메타데이터 포함, 출처 UI와 답변 길이 제한 |
| 문서당 최대 청크 | 2 | 한 문서로 근거가 편중되는 현상 제한 |
| 코사인 거리 상한 | 0.9 | 필수 작품 해설 외 관련성이 낮은 후보 제한 |

기본 원문 분할 결과는 `1000/200` 689청크, `1000/0` 684청크, `600/100` 860청크였습니다.
이는 청킹 차이 확인이며 최적 품질을 입증한 비교 평가는 아닙니다.

### 근거 표시·특화 기능

- **근거 표시:** `[근거 N]`을 누르면 실제 인용한 원문의 제목·링크·발췌·저작자·라이선스를 확인합니다.
  메타데이터와 외부 문서를 구분하고 일반 시대 배경을 개별 작품의 제작 동기로 단정하지 않습니다.
- **근거 부족:** 일반 LLM 지식으로 자동 전환하지 않습니다. 확인된 부분만 설명하거나 근거 부족을 안내합니다.
  인용 검증이 모델 해석의 사실 정확성까지 보장하지는 않습니다.
- **특화 기능:** 기존 작품 문서를 사용해 관찰 → 배경 이해 → 다시 감상의 3단계 가이드를 만듭니다.
  새 웹 수집 없이 `look`, `context`, `reflect`의 텍스트·인용 JSON을 검증하고 단계별 출처를 표시합니다.

### 겪은 문제와 해결

- **작품 이미지 3점의 임베드 실패:** 미술관이 보안 확인 응답을 반환했습니다. 동일 작품 ID·작가·CC0를
  대조한 공개 복제본을 로컬 WebP로 제공하고 출처·해시를 `data/art/local_images.json`에 기록했습니다.
- **반복 수집·색인 중복:** 검색 계획·정규화 검색어·선별 결과를 영구 캐시하고 고정 ID·해시로 증분 색인했습니다.
- **작품·시대 문서 혼입:** 현재 작품 ID와 제작 시기·지역으로 검색 범위를 제한하고 요청별 상태를 분리했습니다.
- **출처 없는 답변:** 근거 한정 프롬프트와 인용 검증을 적용하고 무인용 답변은 근거 부족 안내로 대체했습니다.

OpenLearn은 근세 유럽 19개·네덜란드 황금시대 13개·계몽주의 18개입니다.
질문별 추가 Wikipedia 문서는 별도 캐시에 보관하므로 위 기본 건수와 구분합니다.

자료 전체에 단일 라이선스를 적용하지 않습니다. 개별 원문·저작자·이용 조건과 선별 내역은
[데이터 설명서](data/art/README.md), [OpenLearn 강좌별 조건](data/art/openlearn_sources.json)에 기록했습니다.
제외 대상 원문이 들어 있는 수집 캐시와 `.env`는 제출하지 않습니다.

## 6. 전체 기능

### 필수

| 기능 | 한 줄 설명 |
| --- | --- |
| 데이터 적재·색인 (F2001/F2002) | 작품 100점의 메타데이터를 읽고 중복 없이 임베딩·갱신합니다. |
| 검색어 추출·문서 수집 (F2003/F2004) | 질문에서 검색어를 뽑아 외부 후보를 수집·선별하고 완료한 검색어는 재사용합니다. |
| 외부 문서 청킹·색인 (F2005) | 원문을 문단별로 나누고 출처 정보와 함께 별도 컬렉션에 저장합니다. |
| 근거 검색·병합 (F2006) | 현재 작품 범위에서 문서를 검색하고 중복 제거·출처 수 제한을 적용합니다. |
| RAG 답변 (F2007) | LangGraph 검색·생성 노드로 근거가 있는 내용만 답합니다. |
| 인용·출처 확인 (F2008) | 답변에 사용한 원문 링크·발췌·저작자·라이선스를 확인합니다. |
| 작품별 대화·히스토리 (F2009) | 작품을 넘기면 해당 대화로 전환하고 별도 기록 창에서 다시 봅니다. |
| 작품 감상 가이드 (F2010) | 현재 문서로 3단계 감상 순서와 단계별 출처를 제공합니다. |
| 자연어 작품 탐색 (F2011) | 작가·연도·지역·사조 등 조건으로 작품을 찾고 해당 전시로 이동합니다. |
| 진행·오류 안내 (F2012) | 실제 처리 단계·키/색인 누락·실패·재시도를 안내합니다. |

### 심화(선택)

| 다중 출처 활용 (F2016) | 미술관·Wikipedia·OpenLearn 문서를 함께 검색하고 출처 정보를 구분해 제공합니다. |
